# ATLAS Research Lab — quickstart (English)

[Türkçe README](../../README.md) · [Published scope](../README.md)

ATLAS is a verification-first, multi-agent research lab. This repository is the
mechanism, not the archive: generated papers and corpora are deliberately excluded.

Requirements: `python3` (3.9+), `make`, `git`. No model calls, no network at
verification time, no API keys.

```bash
git clone https://github.com/ali-han-kaya/atlas-research-lab.git
cd atlas-research-lab
python3 -m pip install -r requirements-dev.txt   # pinned: requests, pip-audit
make kur                                         # enable commit/push guards in this clone
```

## 1. `make dogrula` — one entry point, eight checks

```text
  H1  depo hijyeni             PASS    0 bulgu
  H2  python sozdizimi         PASS    59 dosya
  H3  kabuk sozdizimi          PASS    7 dosya
  H4  sir taramasi             PASS    0 bulgu
  H5  sir kapisi oz-testi      PASS    SIR KAPISI OZ-TEST: 6/6 gecti
  T1  ATLAS oz-testi           PASS    ATLAS OZ-TEST: 145/145 gecti
  T2  KOD oz-testi             PASS    KOD OZ-TEST: 174/174 gecti
  T3  Toolkit oz-testi         PASS    ...

  kalem=8 · gecen=8 · kalan=0 · calistirilmadi=0
  HUKUM: PASS — 8/8 kalem gecti
```

Exit code 0. `T1` runs against this repository's `attestation.json`; it no
longer needs the private tree's commit history. If the attestation is missing
or corrupt, `OLG-1` fails rather than being reported as not run. See *OLG-1 and
tree evidence* in the Turkish README. Numbers are printed by the tools, not
maintained by hand.

## 2. `make mutasyon` — do the gates actually fire?

Each case takes a clean baseline (`rc=0`), introduces exactly one violation and
requires a red verdict plus a specific marker. A green baseline without a red
mutation does not pass.

```text
SONUC: 54/54 kural atesledi · 17/17 beklenen bulgu dogrulandi · taban temiz olmayan=0
HUKUM: PASS — her vaka temiz tabanda sessiz, ihlalde kirmizi/beklenen bulgu.
```

Exit code 0. Every published gate rule is listed in
[`../MUTASYON_KAPSAM.md`](../MUTASYON_KAPSAM.md): of 122 rules, **71** are
mutation-tested, **28** are out of scope with a measured reason
(network, secret key, commit history, run state, repo state, or a rule id no
code branch emits), and **23** are explicit gaps — 11 mentioned only in
self-tests, 12 in no test at all. Gaps are
not relabelled as "out of scope". The table is generated by `tools/kapsam.py`;
`make kapsam` fails if it goes stale.

## 3. `./demo` — reproduce the historical failure, on purpose

`DENEME/` is a frozen, deliberately defective run from 23 August 2026: the fix
manifest declared 8 fixes as applied, only 2 reached the master text, and the
gate of that day still said `PASS`.

```text
DEMO — DENEME/ dondurulmus kusurlu kosu (v5.5.2, 23 Agustos 2026)
...
  manifesto iddiasi : 8 FIX "UYGULANMIS"
  MASTER'da gorunen : 2 FIX
  dondurulmus kapi  : PASS  (DENEME/gate/FINAL-GATE-v5.5.json)

  bugunku mutabakat : FAIL  (fix_reconcile, rc=1)
...
HUKUM: FAIL — iddia 8, kanit 2; dondurulmus kapi PASS dedi.
BEKLENEN KIRMIZI — bu komut bilerek rc=1 doner.
```

Exit codes of the canonical `./demo` (measured with `echo $?`):

| State | Code |
|---|---|
| Red — claim > evidence while the frozen gate says PASS | **1** |
| Fixture broken — missing/invalid file, gate not PASS, no expected contradiction | **2** |
| Green — claim == evidence and reconciliation passes | **0** |

`make demo` is a thin wrapper only: GNU make always exits **2** on a failing
recipe, so it cannot carry the 1-vs-2 distinction. Use `./demo` (or
`python3 tools/demo.py`) when the code matters; the red must come from the
claim/evidence gap, not from a broken test.

## What else is measured

| Command | What it proves |
|---|---|
| `make kapsam` | `docs/MUTASYON_KAPSAM.md` matches the current gate inventory |
| `make guvenlik` | `pip-audit` findings, each named in `docs/GUVENLIK.md`; unlisted finding → red |
| `make dogrula-ci` | runner mode used by GitHub Actions (same rules, no CI-only exemption) |
| `make katalog-kontrol` | optional network check: fixed allowlist IDs still exist at models.dev; not run in CI |
| `make oztest` | the three self-test suites alone |
| `make iddia` | numeric claims in README/docs, re-measured with their stored raw evidence line; named by `IDD-*` on mismatch |
| `make iddia-yaz` | regenerate the raw evidence snapshot after an intentional change |

`make iddia` is separate from `make dogrula`: it does not change the 8/8 verdict.
Claims that cannot be re-run are not forced green — `AG_GEREKLI` (network; skipped
unless `make iddia-ag`), `BEYAN` (dated/machine-bound) and `OLCULMEDI` (not
reproducible here) are counted separately with their reason and marked
`ham kanit yok` (no local raw evidence).

CI runs `make dogrula-ci`, `make mutasyon`, `make kapsam`, `make guvenlik`, and
asserts `./demo` exits **1** while `make demo` exits **2** (the wrapper cannot
carry 1). Workflow: `.github/workflows/dogrula.yml`.

`make katalog-kontrol` is deliberately **not** in CI: it requires network. It
exits 1 and names stale/missing IDs, or 2 when the live catalog cannot be read.
For the code distinction, run `python3 tools/katalog_kontrol.py` directly; GNU
make turns a failing recipe into exit 2.
