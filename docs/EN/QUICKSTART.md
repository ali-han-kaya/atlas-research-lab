# ATLAS Research Lab — quickstart (English)

[Türkçe README](../../README.tr.md) · [Published scope](../README.md)

ATLAS is a verification-first, multi-agent research lab. This repository is the
mechanism, not the archive: generated papers and corpora are deliberately excluded.

Requirements: `python3` (3.9+), `make`, `git`. No model calls, no network at
verification time, no API keys.

```bash
git clone https://github.com/ali-han-kaya/atlas-research-lab.git
cd atlas-research-lab
python3 -m pip install -r requirements-dev.txt   # pinned: requests, pip-audit, jsonschema
make kur                                         # enable commit/push guards in this clone
```

Use a full clone, not `--depth 1`: `T1` verifies the attestation against the
commit history, and a shallow clone fails that check.

## 1. `make dogrula` — one entry point, eight checks

```text
  H1  depo hijyeni             PASS    0 bulgu
  H2  python sozdizimi         PASS    <güncel> dosya
  H3  kabuk sozdizimi          PASS    8 dosya
  H4  sir taramasi             PASS    0 bulgu
  H5  sir kapisi oz-testi      PASS    SIR KAPISI OZ-TEST: 19/19 gecti
  T1  ATLAS oz-testi           PASS    OZ-TEST: <güncel>/<güncel> gecti · KANIT commit=<sha> tree=<sha>
  T2  KOD oz-testi             PASS    KOD OZ-TEST: <güncel>/<güncel> gecti
  T3  Toolkit oz-testi         PASS    ...

  kalem=8 · gecen=8 · kalan=0 · calistirilmadi=0
  HUKUM: PASS — 8/8 kalem gecti
```

Exit code 0. `T1` runs only against this repository's `attestation.json`; it has
no historical or private-tree fallback. If the attestation is missing or
corrupt, `OLG-1` fails rather than being reported as not run. See *OLG-1 and
tree evidence* in the Turkish README. Current generated values are in
[`docs/DURUM.md`](../DURUM.md); numbers are not maintained by hand.

**Approximate duration:** 196 s on a fresh `/tmp` clone (macOS 27.2, Python 3.9.6;
one run on 2026-11-24). Timings move with filesystem and start-up cost; a CI
runner may differ.

## 2. `make mutasyon` — do the gates actually fire?

Each case takes a **silent clean baseline** (`rc=0`, with no target finding),
then introduces exactly one violation. The post-mutation contract depends on
the case type:

- **Red-verdict cases** must flip the gate to a red verdict (`rc=1`) carrying
the expected marker.
- **Expected-finding cases** may stay green (`rc=0`), but the expected warning
  or finding marker must appear after the mutation.

A case passes only when the baseline contains no finding *and* its
after-mutation contract holds. A green baseline alone is not enough; a marker
in the baseline fails the case before the mutation is even evaluated.

```text
SONUC: 113/113 kural atesledi · 27/27 beklenen bulgu dogrulandi · taban temiz olmayan=0
SOZLESME: 105/105 HATA (rc=1) · 8/8 TERMINAL (rc=2) · 27/27 BEKLENEN_BULGU
HUKUM: PASS — her vaka temiz tabanda sessiz, ihlalde kirmizi/beklenen bulgu.
```

Exit code 0. Every published gate rule is listed in
[`../MUTASYON_KAPSAM.md`](../MUTASYON_KAPSAM.md): of 117 rules, **93** are
firing-tested (HATA or TERMINAL), **24** are verified only by an expected
finding (P1; not added to the coverage count), and **0** are explicit gaps.
Outside the inventory sit **4** dead identities — header identifiers no code
branch ever emits (DEP-02, API-03, OZT-04, SEC-04) — and **1** external
reference (DEC-027); each carries a measured reason in its own table, and none
of them is counted as a rule. Of the rules that are counted, 0 are mentioned
only in self-tests and 0 appear in no test at all. All nine previous gaps now
have mutation cases; the 27 expected-finding cases (including TST-06, CHK-05 and the
dedicated `QR-02-DENGE` case for the unbalanced-quote warning) are verified by
a marker after the mutation with a silent clean baseline, not by a red verdict.
Dead identities are not relabelled as tested and not silently dropped: they are
named, measured (`tools/kapsam.py --oztest`) and justified row by row. The table
is generated by
`tools/kapsam.py`; `make kapsam` fails if it goes stale.

**Approximate duration:** 169 s on the same fresh `/tmp` clone (macOS 27.2,
Python 3.9.6; one run on 2026-11-24). Each case starts from a silent clean
baseline and gets one mutated run;
FRZ-01 and FRZ-02 each have terminal-contract and missing-file reruns, plus a
combined terminal check. FRZ-08 has three terminal cases (an invalid signature,
a validly signed baseline whose content is changed afterwards, and a validly
signed baseline re-signed with a different key) plus an expected-finding case
for an unsigned `temiz_agac:true` baseline (P1 `DUSUK_GUVEN`). REC-01..06 cases
also restore the fixture and rerun green as a
no-op control; their alternatives cover duplicate FIX-IDs, malformed Gate 2B
JSON/schema and multiple ghost IDs.

## 3. `make yayinla` — publish parity (dry run)

This repository is published from a private lab tree through an explicit
include list. `make yayinla` compares the two and prints the plan; without
`UYGULA=1` it is a **dry run** and writes nothing.

```bash
ATLAS_LAB=<LAB_KOKU> make yayinla
```

```text
YAYIN PLANI · kaynak: <lab path>
  planda=220 · yeni=0 · degisen=0 · ayni=220 · silinecek=0

SIR TARAMASI: temiz (0 bulgu)

PARITE: TEMIZ — 0 yeni / 0 degisen / 0 silinen
```

Exit code 0. A drifted, missing or extra file is named and the command exits
**1** (`PARITE: DRIFT — ...`) before writing anything; `UYGULA=1 make yayinla`
then applies the plan. The same run scans the planned bytes for live
credentials and blocks the transfer on a finding. Runtime files under
`.opencode/` (`package.json`, lockfiles) are ignored in both trees and are not
part of the plan, so the 220-file count is deterministic.

This is a maintainer check: without a lab tree the target stops before writing
— `ATLAS_LAB degiskeni gerekli` when the variable is unset, `HATA: kaynak
dizin yok` for a bad path — both with exit code 2. It is deliberately not part
of `make dogrula`.

**Approximate duration:** under a second (220 files hashed, no subprocesses).

## 4. `./demo` — reproduce the historical failure, on purpose

`DENEME/` is a frozen, deliberately defective run from 23 August 2026: the fix
manifest declared 8 fixes as applied, only 2 reached the master text, and the
gate of that day still said `PASS`.

```text
DEMO — DENEME/ dondurulmus kusurlu kosu (v5.5.2, 23 Agustos 2026)
...
  manifesto iddiasi : 8 FIX "UYGULANMIS"
  MASTER'da gorunen : 2 FIX
  dondurulmus kapi  : PASS  (DENEME/gate/FINAL-GATE-v5.5.json)

  bugunku mutabakat : FAIL  (fix_reconcile, rc=1)
...
HUKUM: FAIL — iddia 8, kanit 2; dondurulmus kapi PASS dedi.
BEKLENEN KIRMIZI — bu komut bilerek rc=1 doner.
```

Exit codes of the canonical `./demo` (measured with `echo $?`):

| State | Code |
|---|---|
| Red — claim > evidence while the frozen gate says PASS | **1** |
| Fixture broken — missing/invalid file, gate not PASS, no expected contradiction | **2** |
| Green — claim == evidence and reconciliation passes | **0** |

`make demo` is a thin wrapper only: GNU make always exits **2** on a failing
recipe, so it cannot carry the 1-vs-2 distinction. Use `./demo` (or
`python3 tools/demo.py`) when the code matters; the red must come from the
claim/evidence gap, not from a broken test.

## 5. `make iddia` — the claim suite

`make iddia` is the entry point for the numeric claims printed in this repository.
Each `OLCULDU` row in `tools/iddia_defteri.json` names the file and exact quote it
supports, the command that produces it, and the expected value. The raw output line
is stored under the same `IDD-*` key in the file named by the ledger's top-level
`olcum_dosyasi` field (`tools/iddia_olcum.json`); `tools/iddia.py` rejects a missing
or different path. The documented summary in `docs/IDDIA-OZET.md` is recomputed from
the ledger on every run, so a stale summary fails with `rc=2` instead of drifting
silently.

A claim you cannot re-run is never forced green: `AG_GEREKLI` (network), `BEYAN`
(dated/machine-bound) and `OLCULMEDI` are counted separately and marked
`ham kanit yok`. Run `make iddia-hizli` for the offline subset; the default
`make iddia` is the full suite. A concrete hand-trace of one row is in the Turkish
README, section *Tek bir iddiayı elle izlemek*.

## What else is measured

| Command | What it proves |
|---|---|
| `make kapsam` | `docs/MUTASYON_KAPSAM.md` matches the current gate inventory |
| `make model-kimlik` | zero retired-ID references in active code/config/tests/docs; every candidate file is inspected (binary-safe, no size cap), the PASS line reports `taranan`/`incelenmedi`/`onay`/`aktif`, an uninspected file without an approval entry fails, and seven named mutants in `make mutasyon` revert each protection |
| `make guvenlik` | `pip-audit` findings, each named in `docs/GUVENLIK.md`; unlisted finding → red |
| `make dogrula-ci` | runner mode used by GitHub Actions (same rules, no CI-only exemption) |
| `make katalog-kontrol` | live models.dev gate: fixed allowlist IDs and all ten `profiller.bedava` roles; network required, run manually outside CI; `OLCULMEDI` fails, never passes |
| `make oztest` | the three self-test suites alone |
| `make iddia` | numeric claims in README/docs, re-measured with their stored raw evidence line; named by `IDD-*` on mismatch. A scope gate also fails for any numeric claim neither quoted in the ledger nor covered by a narrow justified exception (`kapsam.sayisal_istisna`); stale, reasonless or over-broad exceptions are red too |
| `make iddia-hizli` | fast claims only; skips `dogrula`/`mutation` rows, marks them `ATLANDI` and never counts them as PASS; the full run is unchanged |
| `make iddia-yaz` | regenerate the raw evidence snapshot after an intentional change |

The KOD `bedava` profile has binding selection and retirement rules — same
family, zero cost, `reasoning`/`tool_call`, live models.dev evidence, and the
exact retirement procedure. See `docs/KOD_BEDAVA_MODEL_POLITIKASI.md` (Turkish).

`make iddia` is separate from `make dogrula`: it does not change the 8/8 verdict.
Claims that cannot be re-run are not forced green — `AG_GEREKLI` (network; skipped
unless `make iddia-ag`), `BEYAN` (dated/machine-bound) and `OLCULMEDI` (not
reproducible here) are counted separately with their reason and marked
`ham kanit yok` (no local raw evidence).

`make iddia` skips the network claim. `make iddia-ag` requires the live catalog;
if it cannot be read, the claim is reported as `AG` and the command exits **2**
instead of emitting a false PASS or FAIL.

`make iddia-hizli` measures only the fast rows: commands running
`tools/dogrula.py` or `tools/mutasyon_bataryasi.py` are not started, their rows
are printed as `ATLANDI`, and the summary counts them separately — they are
never PASS. The default `make iddia` remains the full run, and `--yaz --hizli`
is refused because a partial snapshot would delete the other rows' evidence.

CI runs `make dogrula-ci`, `make mutasyon`, `make kapsam`, `make guvenlik`, and
asserts `./demo` exits **1** while `make demo` exits **2** (the wrapper cannot
carry 1). The live `make katalog-kontrol` gate runs outside CI; the workflow
does not call it. `make dogrula-ci` includes the offline
`make katalog-selftest` prerequisite. Workflow: `.github/workflows/dogrula.yml`.

`make katalog-kontrol` measures the live models.dev record for all ten
`profiller.bedava` roles: one identity, zero `cost.input`/`cost.output`, live
and local `reasoning`/`tool_call`, non-deprecated `status`, and the configured
`bedava_politika.asgari_limit`. Exit 1 names stale/missing IDs or a broken
bedava condition; exit 2 is **`OLCULMEDI`** when the live catalog cannot be
read. `OLCULMEDI` never becomes PASS. Each run appends a
commit/tree/tree_sha256 and definition-SHA-256 record; pass `--kayit <path>` to
write it to a separate file. For the code distinction, run
`python3 tools/katalog_kontrol.py` directly; GNU make turns a failing recipe
into exit 2.
